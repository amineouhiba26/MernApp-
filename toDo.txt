TP4 : Déploiement d’Applications avec

Kubernetes

Objectifs
Les objectifs de ce TP sont :
— Découvrir Kubernetes pour l’orchestration de conteneurs.
— Déployer une application MERN en utilisant les objets Deployment,
Service et ConfigMap.
— Comprendre le fonctionnement du scaling horizontal et de la mise à jour
continue.
Prérequis
— Avoir réalisé le TP précédent sur l’intégration continue avec Jenkins,
Docker et Trivy.
— Disposer d’un cluster Kubernetes fonctionnel :
— Docker Desktop avec Kubernetes activé.
— Minikube installé et configuré.

— Avoir les outils kubectl et docker installés et configurés sur votre ma-
chine.

Instructions
1. Préparation de l’environnement
Fork puis clonage du projet :
Commencez par forker le projet mern-app dans votre espace GitLab (bouton
Fork sur l’interface GitLab), puis clonez votre fork sur votre machine locale :
git clone https :// gitlab . com / < votre - user >/ mern - app . git
cd mern - app
Remplacez <votre-user> par votre nom d’utilisateur GitLab.
Construction des images Docker :
Naviguez dans les répertoires server et client pour construire les images
Docker :

2. Création du ConfigMap pour la configuration des applications
Créez un fichier nommé app-configmap.yaml contenant un objet ConfigMap.
Consultez la documentation officielle pour comprendre la structure et les champs
requis : Documentation Kubernetes : ConfigMap.
Le ConfigMap doit contenir les variables d’environnement nécessaires pour
que le client, le serveur et MongoDB puissent communiquer entre eux. Par
exemple :
— MONGO_URI : URI de connexion à MongoDB
(par exemple, mongodb://mongodb-service:27017/mern-app).
— REACT_APP_SERVER_URL : URL du serveur pour le client (par exemple,
http://server-service:5000).
— PORT : port sur lequel le serveur écoute (5000).
Exemple de app-configmap.yaml :
apiVersion : v1
kind : ConfigMap
metadata :
name : app - configmap
data :
MONGO_URI : mongodb :// mongodb - service :27017/ mern - app
REACT_APP_SERVER_URL : http :// server - service :5000
PORT : "5000"
Appliquez ce ConfigMap à votre cluster Kubernetes :
kubectl apply -f app - configmap . yaml

3. Création du Deployment et Service pour MongoDB
Créez les fichiers mongodb-deployment.yaml et mongodb-service.yaml pour
déployer une instance de MongoDB.
mongodb-deployment.yaml :
apiVersion : apps / v1
kind : Deployment
metadata :
name : mongodb - deployment
spec :
replicas : 1
selector :
matchLabels :
app : mongodb
template :
metadata :
labels :
app : mongodb
spec :
containers :
- name : mongodb
image : mongo : latest
ports :
- containerPort : 27017
mongodb-service.yaml :
apiVersion : v1
kind : Service
metadata :
name : mongodb - service
spec :
selector :
app : mongodb
ports :
- protocol : TCP
port : 27017
targetPort : 27017
type : ClusterIP
Appliquez ces fichiers :
kubectl apply -f mongodb - deployment . yaml
kubectl apply -f mongodb - service . yaml

10. Scaling et Mise à Jour
— Scaling : Augmentez le nombre de réplicas du Deployment serveur à 5.
kubectl scale deployment server - deployment --
replicas =5

— Mise à jour : Changez l’image utilisée par le Deployment client pour
une nouvelle version (par exemple, [username]/mern-client:v2).
Modifiez le fichier client-deployment.yaml en remplaçant l’image,
puis appliquez les changements :
kubectl apply -f client - deployment . yaml
— Observez les effets sur les Pods et les déploiements :
kubectl get deployments
kubectl get pods
11. Nettoyage des ressources
Supprimez les ressources créées :
kubectl delete -f app - configmap . yaml
kubectl delete -f mongodb - deployment . yaml
kubectl delete -f mongodb - service . yaml
kubectl delete -f server - deployment . yaml
kubectl delete -f server - service . yaml
kubectl delete -f client - deployment . yaml
kubectl delete -f client - service . yaml
